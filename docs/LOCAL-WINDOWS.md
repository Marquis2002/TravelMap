# Windows 本地使用说明

本项目位于 `C:\dev\fun\ex05-myTripWeb`，复用 [thisispivi/TravelMap](https://github.com/thisispivi/TravelMap)，保留原版界面和作者信息。

上游基线：`main` 分支，提交 `d6a3c4165f9d03a31c604a5bf7878a2511fca88f`。本地运行环境为 Node.js **24.14.0**、pnpm **11.21.0**，依赖按原版 `pnpm-lock.yaml` 安装。没有导入作者的旅行记录，也没有预填你的 26 省资料。

## 启动、浏览、停止

1. 双击项目根目录的 **Start-TravelMap.cmd**。等待地址出现，浏览器会打开网站。
2. 电脑浏览：<http://localhost:5173>；电脑编辑：<http://localhost:5174>。
3. 手机与电脑连接同一 Wi-Fi，输入启动窗口中 **Phone (same Wi-Fi)** 后的地址。部署时地址为 <http://10.37.183.94:5173>，换网络后请以启动窗口显示的最新地址为准。
4. 双击 **Stop-TravelMap.cmd** 停止。关闭启动窗口不会停止服务；再次双击启动会复用已有服务。

手机浏览期间电脑必须开机、保持联网且不能休眠。编辑器仅监听 `127.0.0.1:5174`，手机不能使用它。网站监听 `0.0.0.0:5173`。不设置开机自启，不发布公网。

已配置 Windows 防火墙规则 `TravelMap-Local-5173`：仅允许本地子网访问 Node.js 的 TCP 5173。规则覆盖各网络配置文件，以支持被 Windows 标记为“公用”的家庭 Wi-Fi。没有放行 5174。若规则被移除，可双击 **Enable-LAN.cmd** 重建；Windows 会要求管理员授权。重复运行会检查已有规则，不放宽范围。

## 新增旅行与上传照片

1. 在电脑编辑器点击 **New trip**，填写标题、出发城市和日期。城市不存在时点击 **Not in the list? Add the place**，按原版表单补全地点。
2. 创建后添加旅途中停留的城市、到达日期、住宿晚数及交通段。需要继续行程时使用 **Keep travelling…**。页面顶部的保存状态和底部 Validation 会提示保存或资料问题。
3. 在对应城市停留段点击 **Upload photos**，选择 **This computer (media folder)**，拖入或选择本地照片。等待 **Done** / **file added to the gallery** 后关闭上传窗口。
4. 编辑器会生成展示图与缩略图，并自动关联该停留段的相册。待顶部显示已保存后，在网站刷新，打开旅行中的 **Photos…** 查看相册，点击照片查看大图。

照片来源配置在 `apps/travel-map/env/.env`：`VITE_CDN_PATH="/media"`。照片经原版处理后写入 `media/Travels/`，旅行与照片清单写入 `data/`。请保留相机原片，网站生成的压缩图不是原片备份。暂不配置 Bunny CDN，也不把本地视频上传或播放作为本阶段功能；原版视频播放依赖 YouTube。

## 备份与恢复

- 编辑器 **Settings → Backups → Take a snapshot** 创建快照，**Download a copy** 下载旅行资料副本，**Restore** 恢复选中的快照。原版还会在部分删除、导入和照片上传前自动建立快照，最多保留 30 份。
- **快照不包含照片文件。** 完整备份时先等待保存完成并停止服务，再复制 `data/`、`media/`、`.data-snapshots/` 以及 `apps/travel-map/env/.env` 到另一块磁盘。
- 恢复完整备份时先停止服务，再放回对应目录与配置，之后重新启动。快照恢复不撤销照片文件的变动。
- `data/`、`media/`、快照和 `.env` 默认被 Git 忽略；代码提交或拉取不等于备份个人资料。

## 常见问题

| 情况                              | 处理                                                                                                                          |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 提示 Port 5173 / 5174 is occupied | 对应端口已被其他程序使用。自行关闭占用程序后重试；启动器不会结束其他程序，也不会改用别的端口。                                |
| 浏览器打不开                      | 重新双击启动。错误日志在 `.local-runtime/website.err.log` 和 `editor.err.log`，普通日志为同目录的 `*.out.log`。               |
| 手机打不开，电脑可以              | 确认同一 Wi-Fi、最新地址、电脑没有休眠；访客 Wi-Fi 或 AP 隔离可能禁止设备互访。必要时运行 Enable-LAN.cmd 检查规则。           |
| 新照片暂未出现                    | 等待上传与自动保存完成，再刷新网站；仍未更新则停止后重启。不要同时在多个编辑标签页修改同一旅行。                              |
| 地图或地点搜索加载不全            | 保持联网；沿用原版外部地图资源，不保证完全离线运行。                                                                          |
| Dependencies are missing          | 按下面的依赖恢复命令安装，再双击启动。                                                                                        |
| 停止时无服务，但端口仍被占用      | 启动器只停止本项目记录且身份匹配的进程。手动启动的服务需在原终端中停止。不要在服务运行时删除 `.local-runtime/services.json`。 |

## 维护命令

在项目根目录的 PowerShell 中执行。固定版本 pnpm 安装在项目的 `.local-tools/`，没有替换系统 pnpm。首次重建该工具目录需要联网。

```powershell
npm.cmd install --prefix .local-tools --no-save --package-lock=false pnpm@11.21.0
$env:PATH = "$PWD\.local-tools\node_modules\.bin;$env:PATH"
pnpm.cmd install --frozen-lockfile
pnpm.cmd check
pnpm.cmd build
```

日常启动不需要重新安装或构建。启动器直接调用已安装的 Vite，管理本项目两个 Node 进程，并核对进程 ID、创建时间和可执行文件后才停止它们。当前使用开发服务；静态构建、正式发布、中文化、省份点亮和年龄目标属于后续阶段。

本地适配只涉及固定端口、监听地址、Windows 数据目录监听、启动停止脚本和局域网防火墙入口，没有新增业务 API 或改变旅行资料结构。原版说明见 [GUIDE.md](./GUIDE.md)。
